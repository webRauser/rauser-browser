# Checked backlinks and recorded arrivals

**Goal.** Show **Linked from** and **Arrived via** independently in This page and Artifact Explorer. A checked sighting of A linking to B should appear on B's recognized card before B has any activity. A later attributed navigation supplies a separate arrival. Keep **Links to** as the latest usable scan and label backlinks as dated historical observations.

**Architecture.** Add a target occurrence index to the existing rebuildable SQLite cache. Derive it from the same checked observation winners as the existing outbound projection. Read backlinks by checked target ID and reuse the existing incoming-trail projection for arrivals. Return both through existing detail exchanges and render them in separate groups outside Explorer's ranked connections and map.

**Tech Stack.** Rust, rusqlite and transactional cache replay, native protocol v8 with generated Rust and TypeScript, existing MV3 panel and Explorer, and the scripted-host and routed headless Chromium fixtures.

**Sources.** Brauser DESIGN.md §§5.1, 5.5, 5.7 and 6.7, the v8 protocol schema, the owned capture and SQLite writers, the panel and Explorer controllers, and the existing joined outbound links fixture.

## Design challenge

- **Challenger.** Independent read-only source review and in-memory SQLite diagnostic.
- **Alternative.** Scan existing checked JSON bodies for target membership, with either a result cap or a hard input cap.
- **Outcome.** Adopt the target occurrence index. In the challenge's in-memory SQLite diagnostic a rare hit and a miss each decoded all 12,000 observation bodies despite an output cap. A 512-body input cap missed the rare hit. A target-key index found it without inspecting unrelated bodies. The diagnostic establishes the query-shape problem. The implementation will measure actual SQLite plans and skewed target fan-in.

## Evidence contract

| Input | Links to on the checked source | Linked from on a recognized target |
| --- | --- | --- |
| Complete list with B | Show B in the usable scan with the observation date and scope. | Show the recorded source with the date, scope and coverage of its latest positive. |
| Later complete list without B | B is absent in that inspected document at that time. A complete empty scan can show measured empty. | Preserve an earlier dated sighting of B while it and its backing source evidence remain in the library. |
| Later partial list | Show the inspected portion with a reason. An omitted B has unknown coverage. | A positive can refresh the row. A missing target leaves the earlier sighting alone. |
| Later unavailable attempt | Show the attempt and the older usable list, if present, with its original date. | The attempt contributes no positives. It leaves earlier dated positives alone. |
| Legacy history without a checked marker | Show that links were not collected. | No source recorded in eligible checked evidence. Omission carries no statement about past contents. |
| No usable library snapshot or an unsupported detail reply | Show evidence unavailable or unsupported through the existing detail state. | Keep successful empty, truncated and unavailable states distinct. |

A scan cannot prove removal of a historical link. Capture stores a second-resolution time and checked scope. Activity commonly scans the top document and summary capture uses `selected_document`, including frame zero. The checked source key belongs to the activity or summary owner. A distinct iframe URL is context for extraction. A selected frame ID is local to the capture context. Even identical stripped URLs can hide changes in route, mode or stripped query values, and comparable scans can race or share one instant. A complete list speaks only for eligible rendered links inspected in that document and observation. Display the original offset on the positive's time. Order distinct observations by UTC instant descending, observation key descending and stable source ID. A UUID tie-break gives repeatable selection within a second. Separately, the earliest durable log position wins conflicting copies of a single observation ID.

Backlinks use only complete checked winning markers. A source requires an indexed owned activity or summary event that agrees on kind, UUID, exact timestamp and normalized URL, plus recorded raw source ID and type. Require a durable log position and a recorded source artifact for the row action. A recorded URL-keyed summary may qualify as a source on that basis. Reuse the indexed event's stored fields. A stage fingerprint protects publication and is not available as replayed marker evidence. If an edit removes the source or changes its binding, discard that occurrence for this view and consider the next matching positive for that source. A legacy source with unknown stripped-name provenance may still support a genuinely checked observation. A legacy visit alone supplies no backlink. Prefer the safe recorded source title with its checked source URL. Use the source ID as a title fallback. An anchor label describes its destination. Never use the iframe URL, a stripped URL rematch, title, category, or present-day adapter policy to manufacture an identity. Keep existing capture admission and source-file dirtiness behavior.

**Arrived via** reports recorded navigation from recognized artifacts using the latest recorded local day for each known source/transition pair. The worker can attribute a same-tab link or form submission to the previous recognized artifact and a new-tab navigation to a recognized opener via `onCreatedNavigationTarget`. The latter can include a script-opened tab and the stored transition label alone cannot establish the user's gesture. Trail delivery is an hourly aggregate with at most ten distinct source/URL/transition triples. Folded edges keep a day, may combine repeated observations and omit sources outside supported attribution. Keep known sources independent of link observations, connection ranking, and category, mention or containment. Unattributed trails, unknown transitions, self edges, missing source records and forward/back are excluded. A recorded visit can have no known source. Render the transition as recorded navigation and **Last recorded [local date]**. Avoid an exact count, time or current-tab arrival claim.
